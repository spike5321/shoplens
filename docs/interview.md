## 五个深挖问题

### 1. 为什么提示词里写“只读”还不够？

沿 `query_model → query_plan → query_executor` 说明：模型输出不受信任；服务器持有修复/调用/日期边界；SQLGlot 检查 AST 中实际引用和函数；计划校验约束口径；reader 无业务原表写权限；只读事务、3 秒超时与 200 行限制约束执行。指出允许列表不是任意 SQL 安全证明。举 DROP/原表读取被阻断和真实权限集成测试，不能只讲字符串过滤。

### 2. 九单 fixture 如何防止“退款或订单重复算”？

手算相同金额的两个订单仍是两个订单；跨类别订单在各类别分别计数，组间不可相加；一明细多次成功退款按事件累加；跨期退款使用完成日期。结合 migration 的视图定义和 `data/reference.py` 原始记录算法说明不同路径交叉核对；客单价分母 DISTINCT order_id、零分母返回空值，总体不能平均类别客单价。

### 3. LangChain 和 LangGraph 各解决什么，哪些代码是项目写的？

LangChain 的 ChatDeepSeek、消息、结构化输出/工具调用是第三方能力；LangGraph 的 StateGraph、路由、interrupt、Command 和 PostgreSQL saver 是第三方。项目定义 QueryPlan/SqlDraft、图节点与限制、语义/AST 校验、报告、会话层和评分。比较显式图与 `create_agent` 学习样例，说明为何不把标准答案或管理员连接工具交给模型。[参考记录](references.md) 只记录实际阅读/使用，不冒称审计 WrenAI/Vanna 全部代码。

### 4. 澄清暂停后关服务，如何继续？为什么不能声称恰好执行一次？

先把 waiting 状态写入数据库，再在单独 clarify 节点 interrupt；恢复节点可能重放，所以中断节点前不调用模型/执行 SQL。服务端生成 owner/run/thread，数据库 checkpoint 用 app 账号；澄清 UPDATE 同时匹配 owner/status/revision/有效期，重复返回 409。已完成结果和等待任务可以读取/继续；运行中任务重启标 interrupted，重试生成新 run。多副本、任务队列、去重写操作不在当前范围。

### 5. 为何“可执行率”不能代表“答对率”？修复为何没提高？

从完整 JSONL 举总客单价错误加 day GROUP、退款渠道 Top 2 被错误拒绝、冻结空数据生成两条 SQL 等失败。评分独立计算数值/空值/排序/Top N 与交互预期；执行通过不保证口径。三配置固定模型温度/数据/权限，40 开发 +40 冻结共享指标但按问题模板族隔离；冻结题已曝光，之后迭代不再称盲测。一次修复对计划层错误无效，0/8 SQL 修复成功；保留 88.6%→85.7% 真实结论。总 Token 与价格日期分开，未核实价格不算人民币费用。
